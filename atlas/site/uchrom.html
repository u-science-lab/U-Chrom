The software behind the atlas

One data structure for the 3-D genome

U-Chrom (Universal Chromatin) is a Python toolkit for chromatin 3-D structure data. Chromatin tracing, single-cell and spatial Hi-C and 3-D reconstructions all become one container, ChromData, which every analysis module and the browser share.

Data model

ChromData

Every row of a ChromData is a spot: one locus of one copy of a chromosome in one cell, with its x, y, z when it has them. Spots are stored flat and read by cell, trace or chromosome; the loci live once, on an axis that all cells share.

  • Contacts stay contacts. Contact maps are kept as maps, linked or embedded, never forced into coordinates; distances are computed per trace on demand rather than stored as matrices.
  • Results keep their provenance. Called TADs, loops and compartments carry the function, parameters, inputs and U-Chrom version that made them.
  • FOF-CT in and out. The 4DN FISH Omics Format core table maps onto ChromData one to one, in both directions.

On disk

.chromdata.zarr

A ChromData is written as a Zarr v3 group of Parquet tables and Zarr arrays: open formats that any language can read. Coordinates are partitioned by chromosome and sorted by cell, and contact maps are sharded, so a reader fetches only what it needs, from a disk or over HTTP.

x.chromdata.zarr/
  zarr.json                      format version, metadata, provenance
  tables/bins.parquet            the locus axis
  tables/cells.parquet           cells; traces, intervals alike
  tables/coords/chrom=chr1/…     x, y, z + ids, per chromosome
  tables/primary/*.parquet       per-spot tracks, sorted by cell
  index/                         row ranges of every cell and trace
  embedded/contacts/<map>/       per-cell and bulk maps, by chromosome
  embedded/anndata/<key>/        RNA, ATAC, A/B
  embedded/images/<key>          tissue images
  • Read on demand. Opening an atlas dataset over HTTP takes about seventeen small requests; a cell, a chromosome or one region of a contact map is a range read.
  • Self-contained. Contact maps, RNA and images can be embedded, so one store holds the whole dataset.
  • One file when you want it. .cdz is the same tree in one uncompressed zip: the atlas' download format, opened like the directory.
  • Versioned. Format 2.3; newer readers read older stores, and older formats convert in one command.

The package

Modules

The modules meet in ChromData. Analysis functions share one calling convention: a chromosome, cell or trace selection, typed parameters, and the result stored under a key with its provenance.

uchrom.core

ChromData, the .chromdata.zarr format, backed and remote reading

uchrom.io

.pairs, .cool / .mcool / .scool, .hic, .3dg, PDB, FOF-CT, seqFISH+ multi-omics

uchrom.recon

3-D reconstruction: NucDynamics and GEM for single cells, MDS for bulk Hi-C, GEM-FISH for Hi-C with FISH

uchrom.im

Imaging: assigning spots to traces, imputing missing coordinates

uchrom.strc

Structures: TADs (directionality index, ArcFISH, FISHnet), loops, A/B compartments

uchrom.fea

Per-locus features: distances, sequence, gene annotation, peaks

uchrom.emb

Single-cell embeddings: Higashi, scHiCluster-style Hi-C features, RNA and ATAC

uchrom.browser

The interactive browser, desktop and web; the atlas runs the web browser

A first look

An atlas dataset in Python

The same stores the atlas shows, opened from Python: nothing is downloaded until it is used.

from uchrom import ChromData

cd = ChromData.read(
    "https://uchrom-atlas-r2.u-science.org/stevens2017_mesc.chromdata.zarr",
    backed=True,                                           # read on demand, over HTTP
)
cd.cells                                                   # one row per cell
cell = cd.get_cell("Cell_1")                               # its 3-D genome structure
dist = cell.compute_distances(trace_id="Cell_1_chr1")      # chr1 distance matrix
clr = cd.load_linked_scool(key="per_cell", cell="Cell_1")  # its contact map (cooler)
