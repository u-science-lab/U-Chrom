# Supplementary Table S1 — What each format can represent (evidence for Fig. 2b)

Generated by `benchmarks/fig2/b_capabilities.py` from `paper/fig2/results/b_capabilities.json`; do not edit by hand.

**Marks.** ● *native*: first-class, with its own structure. ◎ *linked*: kept in an external community-standard file (not copied) and queried through the shared index. ○ *by convention*: stored and read back through the library's public API, but only in a general-purpose slot (`uns`, `obsm`, `varp`, `attrs`, extra or optional columns), so the structure is lost or ad hoc. – *not supported*: no place for it in the format or its API.

**Rules.** (1) The evidence decides; only where it is genuinely ambiguous does the other tool get the better mark, and the note starts with *Judgement call*. (2) AnnData has a single observation axis: each element is rated in its most favourable orientation (spots, cells or loci as `obs` / `var`), although these orientations exclude each other in one object; the hierarchy column is where that shows (the same holds for a SpatialData table, which is an AnnData). (3) A test that needed a general-purpose slot can back at most *by convention*, one that needed an external file *linked*; the script fails on any inconsistency. (4) A data table serialised to JSON text inside a descriptive metadata attribute (cooler's `metadata`) does not count; such tests are still run and reported as *not counted*. Parameters / software records (provenance) there do count; the result itself must be stored as data. (5) *Partial reads*: native when one cell's or one chromosome's rows are read from disk without reading the other rows (beyond the selection key column); by convention when that is only possible by scanning every row (streamed, memory bounded) or with part of the data (e.g. `obs` / `obsm`) loaded whole.

**Tests.** ✓ = a tiny test in `benchmarks/fig2/b_capabilities.py` stored the element with that library's own API, wrote it to disk, read it back and compared the values; the slot it used (dedicated / generic / external) is given. FOF-CT is a CSV specification, not a library, so its row rests on the specification pages (core, trace, cell, mapping, bio, quality, rna, subcell and the format overview) alone.

**Versions checked.** uchrom 0.2.0; anndata 0.12.11; spatialdata 0.7.2; mudata 0.3.4; cooler 0.10.4; zarr 3.1.6; h5py 3.16.0; FOF-CT v1.0 (specification pages checked 2026-09-26).

| Container | Element | Before | After | Reason |
