# Supplementary Table S1 — What each format can represent (evidence for Fig. 2b)

Generated by `benchmarks/fig2/b_capabilities.py` from `paper/fig2/results/b_capabilities.json`; do not edit by hand.

**Columns.**

- *spot coordinates (x, y, z)*: the x, y, z position of every spot (one imaged or reconstructed locus in one trace), with its unit.
- *cell › trace › spot hierarchy*: which trace and which cell each spot belongs to, as nested levels rather than loose labels.
- *per-spot signals*: values measured per spot, such as immunofluorescence intensity or z-scores at that spot.
- *per-locus (bin) signals*: values per genomic bin shared by all cells, such as bulk ATAC / ChIP tracks or GC content.
- *cell table*: a table of scalar properties per cell, such as cell type, volume or RNA counts.
- *cell embeddings (multi-dimensional)*: a multi-dimensional vector per cell, such as a PCA, UMAP or learned embedding.
- *cell spatial position (centroid / outline)*: where each cell is in the tissue or field of view (centroid and / or outline), with unit and coordinate frame.
- *contact maps*: locus × locus contact counts (Hi-C-type maps), in bulk or per cell.
- *genomic intervals (TADs / loops)*: genomic intervals and interval pairs called on the data, such as TADs and loops.
- *non-genomic points (RNA spots)*: 3-D points that are not genomic loci, such as RNA spots or protein puncta.
- *analysis results with provenance*: analysis results stored as data together with the function, parameters and version that produced them.
- *partial reads by cell / chromosome*: reading one cell's or one chromosome's rows from disk without reading the rest of the data.

**Marks.** ● *native*: first-class, with its own structure. ◎ *linked*: kept in an external community-standard file (not copied) and queried through the shared index. ○ *by convention*: stored and read back through the library's public API, but only in a general-purpose slot (`uns`, `obsm`, `varp`, `attrs`, metadata attributes, extra or optional columns), so the structure is lost or ad hoc. – *not supported*: no place for it in the format or its API.

**Rules.** (1) The evidence decides; only where it is genuinely ambiguous does the other tool get the better mark, and the note starts with *Judgement call*. (2) AnnData and MuData are rated in their most favourable orientation (spots, cells or loci as observations), and these orientations exclude each other in one object (one AnnData, one MuData modality; a MuData can hold one modality per orientation, linked only by `obs` columns). The hierarchy column is where that shows; the same holds for a SpatialData table, which is an AnnData. (3) A test that needed a general-purpose slot can back at most *by convention*, one that needed an external file *linked*; the script fails on any inconsistency. (4) A data table serialised to JSON text inside a descriptive metadata attribute (cooler's `metadata`) does not count; such tests are still run and reported as *not counted*. Parameters / software records (provenance) there do count, and so do scalar key-values that describe the object carrying the attribute (each cell's own cooler in a `.scool`), as a general-purpose slot; the result itself must be stored as data. (5) *Partial reads*: native when one cell's or one chromosome's rows are read from disk without reading the other rows (beyond the selection key column); by convention when that is only possible by scanning every row (streamed, memory bounded) or with part of the data (e.g. `obs` / `obsm`) loaded whole.

**Tests.** ✓ = a tiny test in `benchmarks/fig2/b_capabilities.py` stored the element with that library's own API, wrote it to disk, read it back and compared the values; the slot it used (dedicated / generic / external) is given. FOF-CT is a CSV specification, not a library, so its row rests on the specification pages (core, trace, cell, mapping, bio, quality, rna, subcell and the format overview) alone.

|---|---|---|---|
| spot coordinates (x, y, z) | ○ by convention | extra bin columns x, y, z: one structure per file (or per cell of a .scool, one column set per trace); no spot table ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) extra bin columns x, y, z (one structure per file) |
| cell › trace › spot hierarchy | ○ by convention | cells are the .scool cell groups, each with its own bins table (create_scool takes one per cell); traces only as sets of extra bins columns (x_<trace>, y_<trace>, z_<trace>), spots as bins rows (test) ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) cells = .scool cell groups (each with its own bins table); traces = sets of extra bins columns x_<trace>, y_<trace>, z_<trace>; spots = bins rows |
| per-spot signals | ○ by convention | one extra bins column per trace (intensity_<trace>) in each cell's bins table (test) ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) one extra bins column per trace (intensity_<trace>) in each cell's bins table |
| per-locus (bin) signals | ● native | bins table, which the schema allows to carry extra columns (e.g. weight, signals) ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (dedicated slot) bins table column |
| cell table | ○ by convention | no cell table, but every cell of a .scool is a cooler with its own metadata attribute: the cell's properties as scalar key-values there (cooler.create_cooler on /cells/<name>, test); the table is rebuilt by opening every cell group ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) each cell's properties as scalar key-values in the metadata attribute of its own cooler (/cells/<name>), written with cooler.create_cooler(uri, ..., metadata=); a scan of every cell group rebuilds the table |
| cell embeddings (multi-dimensional) | ○ by convention | Judgement call: no per-cell arrays; one scalar key per dimension (umap_1, umap_2) in each cell's metadata works (test), as FOF-CT's one optional column per dimension, which is also rated by convention. Awkward for a 64-dimensional embedding; an embedding matrix as JSON in one attribute is not counted ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) one scalar key per embedding dimension (umap_1, umap_2) in each cell's metadata, as FOF-CT's one column per dimension |
| cell spatial position (centroid / outline) | ○ by convention | centroid_x / centroid_y (+ a unit key) in each cell's metadata (test); no coordinate frame, no outline ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) centroid_x / centroid_y (+ a unit key) in each cell's metadata; no frame, no outline |
| contact maps | ● native | pixels (bulk .cool; per cell .scool; multi-resolution .mcool) ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (dedicated slot) pixels |
| genomic intervals (TADs / loops) | ○ by convention | domain membership as a per-bin label column of the bins table (data, not JSON); loops (pairs) have no place ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) per-bin domain label column |
| non-genomic points (RNA spots) | – not supported | no place for non-genomic points; JSON text in the metadata attribute works for 2e5 spots (test) but is not counted ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ not counted: 2e5 RNA spots as JSON text in the metadata attribute (stored; not counted, rule 4) |
| analysis results with provenance | ○ by convention | the result as data (a bins column, as for intervals) and its parameters in the free-form JSON metadata attribute next to generated-by / creation-date (provenance metadata counts under rule 4; a result table as JSON would not) ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (generic slot) result as a bins column, its parameters as JSON in the metadata attribute |
| partial reads by cell / chromosome | ● native | indexed fetch by genomic region (bin1_offset / chrom_offset indexes); one cell group of a .scool ([schema.html](https://cooler.readthedocs.io/en/latest/schema.html)) | ✓ (dedicated slot) indexed fetch('chr2'); one cell group of a .scool |
