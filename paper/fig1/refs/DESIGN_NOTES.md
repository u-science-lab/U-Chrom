# Fig 1 redesign: reference figures and design brief

Collected 2026-09-24. There are 18 reference Fig 1s in this folder. `contact_sheet.png` shows all of them next to the current draft (orange frame). The recommended references have blue frames.

> **Hard constraint found while researching.** Genome Biology's submission guidelines allow **85 mm** (half width) or **170 mm** (full width) figures. The **maximum height is 225 mm including the legend**, lines must be at least 0.25 pt, fonts must be embedded, and raster content should be about 300 dpi
> ([Genome Biology submission guidelines](https://genomebiology.biomedcentral.com/submission-guidelines/preparing-your-manuscript)).
> The draft is **180 × 208 mm**, so it would be scaled to 94 %. The 4.2 pt labels would print at about 3.9 pt, and a 208 mm figure leaves only about 17 mm for the legend. **Redesign at 170 mm × ≤ 185 mm.**

## 2. Per-figure design analysis

### 1. SpatialData (Nat Methods 2025): best overall match
- **Grid:** a titled figure ("SpatialData framework" plus logo) above a 2-column module grid with 6 boxed panels (a–f). Panel b, the Python library, is the hero at about 40 % of the area.
- **Data structure:** an isometric stack of layers (images → labels → points → shapes). The stack is shrunk into a **logo glyph** and reused everywhere as the SpatialData "object": in c the readers feed it, and in e it is batched for PyTorch. The five element types in panel a are small square icons with one-word labels.
- **Typography:** one sans family (Helvetica/Arial). Panel titles are blue, regular weight and larger than the body. Body text is black. There are only about 3 sizes.
- **Colour:** white background, black 1.5 pt rounded panel frames, and a single blue accent for titles. Data icons use saturated primaries on small areas only.
- **Icons:** flat vector, uniform stroke weight, all drawn in one style. Third-party logos (OME, Zarr, PyTorch, MONAI) are the only external art.
- **Whitespace:** generous inside panels. The frames are tight and evenly gutted.
- **Schematic vs real data:** almost entirely schematic. One real screenshot (napari annotation, panel d) is framed like any other icon.
- **Professional because:** one line weight, one accent colour, a recurring glyph, a strict grid, and short noun-phrase titles.
- **Avoid:** the black frames around every panel are heavy. Thin grey frames or none would suit a denser figure.

### 2. MuData / muon (Genome Biol 2022): closest data-model analogue
- **Grid:** a single row with 3 panels (a 25 %, b 45 %, c 30 %).
- **Data structure:** (a) an isometric, exploded "container → modalities → matrices" stack, with labels on the right at each level. (b) The container is drawn as horizontal bands, one per modality, each showing *real* embedding thumbnails in grey with the modality colour highlighting a subset. (c) The on-disk `.h5mu` HDF5 tree is set side by side with the in-memory `MuData` object tree, joined by arrows. This is exactly the ChromData ↔ `.h5cd` story.
- **Typography:** a rounded geometric sans (Rubik-like). Bold is used for object names (`mod`, `rna`, `atac`) and light grey for types ("HDF5 group"). This two-tone *name : type* pattern is very clean.
- **Colour:** 3 semantic colours (green = MuData, blue = RNA, orange = ATAC), always used together with grey. Very light tints appear only as gradient washes.
- **Whitespace:** a lot. The grey keeps the busy thumbnails calm.
- **Schematic vs real data:** real UMAPs are desaturated to grey, and the semantic colour marks only what matters.
- **Avoid:** the text is very small and light-grey text on white loses contrast in print.

### 3. Vitessce (Nat Methods 2025)
- **Grid:** 3 full-width rows: a) real app screenshots across three environments, b) the configuration model as a box diagram, c) the data-type model.
- **Data structure (panel c):** the most relevant part. On the left is an Observations (cells/beads/spots) × Features (protein/RNA/chromatin) conceptual diagram. In the middle are observation × feature matrices whose **column header bars carry the semantic colour** (orange = feature type, purple = coordinates/image). Matrices are drawn as pixel grids tinted by modality, and faded where a modality is absent. On the right is a fan-out to derived types.
- **Typography:** regular-weight sans throughout. Hierarchy comes from size and position, not bold. Axis-like rotated row labels ("Cell ID", "Bead ID").
- **Colour:** mostly greyscale line art plus a few tinted matrices. Colour encodes data type only.
- **Iconography:** a mixed bag (clip-art cells, a microscope photo, flat icons). Weaker.
- **Schematic vs real data:** real screenshots are confined to a separate top band. They do not mix with the schematics.
- **Avoid:** the thin 1 px boxes in b look like UML. The clip-art in c clashes with the flat matrices.

### 4. scvi-tools (Nat Biotech 2022)
- **Grid:** row a is a left-to-right 4-stage pipeline (data → QC → scvi-tools → downstream). A callout triangle zooms the scvi-tools box into row b: a 3 × 3 grid of task vignettes plus a code block that spans the height.
- **Data structure:** cells × genes matrix glyphs, grey-blue with coloured side bars for annotations. The same matrix glyph repeats in every vignette.
- **Typography:** bold Helvetica stage headers (about 8 pt), regular labels (about 7 pt) and a syntax-highlighted monospace code block. The hierarchy is clear.
- **Colour:** slate blue-grey (#4a5a7a-ish) for all structure. Modality colours (RNA blue, CITE red, spatial purple, ATAC orange) are used **only on text and small glyphs**.
- **Schematic vs real data:** two small real thumbnails (a QC scatter and a UMAP) sit inside pipeline boxes, and everything else is schematic.
- **Professional because:** one neutral structure colour, colour used as text, and the "zoom-in" connector.
- **Takeaway for U-Chrom:** a short `cd.*` code block ("consistent user experience") is a strong, cheap signal for a Python framework paper.

### 5. Nucleome Browser (Nat Methods 2022): domain reference
- **Grid:** a) a circular module diagram on the left (about 35 %); b–d) annotated real screenshots.
- **Data structure:** not a data model. It is a hub-and-spoke "event dispatcher" wheel whose spokes are components (genome browser, 3D structure, OMERO, HiGlass…), each with a thumbnail.
- **Typography:** labels in pastel callout boxes (light blue for components, pale yellow for actions).
- **Colour:** many pastel fills (rainbow gradient ring). Busy.
- **Schematic vs real data:** real Hi-C maps, FISH images and 3-D polymer renderings together, with callouts on top. This shows how to present Hi-C, imaging and 3-D structures in one figure.
- **Avoid:** the rainbow ring and the many callout colours. Too many shapes compete. Emulate only the real-data panels.

### 6. ArchR (Nat Genet 2021)
- Dense 9-panel figure. Panel a is a tall two-column workflow: boxed steps on the left, grouped into colour-tinted stages (pink, yellow, green, blue), with dashed arrows to a column of real-data thumbnails. Panels b–i are benchmarks.
- **Good:** the step → thumbnail mapping with dotted leaders, and consistent small thumbnails.
- **Avoid:** four pastel stage colours carry no meaning, and the benchmarks make Fig 1 overloaded.

### 7. scverse (Nat Biotech 2023)
- 2 panels. a) Nested rounded containers (data structures ⊂ core ⊂ ecosystem ⊂ use cases) with soft blue and yellow fills. b) An hourglass "community" diagram.
- **Good:** nested containment shows the architecture without arrows, and the AnnData/MuData icons are tiny multi-colour block glyphs.
- **Avoid:** mostly logos and text lists, with no real data. It works for a perspective article, not for a methods paper.

### 8. Squidpy (Nat Methods 2022)
- 3 stacked pill-shaped panels (inputs → data structures → analyses) joined by arrows, with a grey "ecosystem" tab behind each pill.
- **Good:** a very bold, simple vertical story. Flat icons have thick black outlines and saturated fills, and there is a small consistent palette (red/orange/yellow/green/blue spots).
- **Avoid:** the heavy 3 pt outlines look cartoonish at 170 mm, and the pills waste corner space.

### 9. SnapATAC2 (Nat Methods 2024)
- Row a: 4 coloured stage headers (muted pink/green/blue/tan), each with a short 3-step text list and one real-data thumbnail on a light grey tile. Rows b–e: algorithm and benchmarks.
- **Good:** *light grey tile behind each thumbnail* unifies heterogeneous plots, and the stage header chips are compact.
- **Avoid:** the arrow-chevrons are heavy, and the four stage colours are not semantic.

### 10. CellRank 2 (Nat Methods 2024)
- One schematic: kernels (6 boxed icons) → transition matrices → "+" → estimator → downstream box. A giant pale-grey arrow on the left names the levels.
- **Good:** the repeated small heatmap glyph and a two-colour legend (blue = v1, orange = v2) for provenance.
- **Avoid:** thick black connectors. The huge grey arrow takes 12 % of the width.

### 11. Giotto (Genome Biol 2021)
- a) A hand-drawn tissue → coordinates + matrix → analyses flow. b) The web viewer. c) A real-data scatter of technologies (cells × features) with thumbnails.
- **Good:** in panel c, each real dataset is a thumbnail joined by a dashed leader to its point on a plot, which is a nice "breadth of support" device.
- **Avoid:** saturated blue heatmap, capital "A." panel labels, clip-art cells and a lot of dashed lines.

### 12. MOFA+ (Genome Biol 2020)
- a) Matrix-factorisation schematic with blocks tinted by view (red/blue, green). b) Downstream outputs as small real plots.
- **Good:** rendering the data matrices as textured pixel blocks with large italic math labels ($Y^m_g$) makes an abstract model concrete. The stacked-3-D variance cube is elegant.
- **Avoid:** the noisy random-pixel texture draws the eye too much.

### 13. scArches (Nat Biotech 2022)
- Schematic of the network (a, b) above real UMAP results (c–e).
- **Good:** the fixed (grey) vs trained (black) line weight is a crisp visual encoding.
- **Avoid:** mixed icon styles (brain, organs, mouse clip-art) and heavy dotted boxes.

### 14. Seurat v5 (Nat Biotech 2024)
- a) Real heatmap → "bridge" box → real modality thumbnails. b) A long vertical matrix-algebra flow with modality-coloured outlined boxes (blue = RNA, magenta = ATAC, grey = multiome).
- **Good:** colour lives only in the box outlines, and the empty interiors keep it light.
- **Avoid:** too tall, with a lot of empty space on the right of b. The underlined italic lists read as text slides.

### 15. HiGlass (Genome Biol 2018)
- A 4-panel conceptual diagram of view linking. Each view is a stylised yellow-orange Hi-C tile with a pill label. Coloured frames encode the locus, and a symbol legend sits at the bottom right.
- **Good:** a *stylised contact-map glyph* that reads as Hi-C instantly, and the colour of the frame = the identity of the locus.
- **Avoid:** repetitive. Many identical tiles.

### 16. cooltools (PLoS Comput Biol 2024)
- A single-row ecosystem strip: DNA reads → pairs → Hi-C map → features, with tool names in grey pill badges on curved arrows.
- **Good:** very sparse and confident. It uses one real Hi-C map, and tool names ride *on the arrows* instead of in boxes. A clean way to name `uchrom.recon` / `uchrom.im`.
- **Avoid:** oversized type relative to the figure.

### 17. 4DN FOF-CT (preprint 2025)
- A detailed illustration of a cell (tissue → nucleus → trace) linked by leader lines to 12 numbered table cards.
- **Good:** domain vocabulary (cell → trace → spot) shown by *zooming into a nucleus*. The card design (number chip plus table name plus key columns) is directly reusable for ChromData's tables.
- **Avoid:** too much small text, and a low-contrast painterly background.

### 18. Scanpy (Genome Biol 2018)
- A big U-shaped arrow ribbon (preprocessing → visualisation → clustering → DE → pseudotime) filled with real default-style plots, plus benchmarks.
- **Good:** an honest "these are real outputs" feel.
- **Avoid:** default matplotlib styling, mismatched fonts inside the thumbnails, and the unaligned grid. It is dated.

## 3. Cross-cutting lessons

1. **One hero glyph for the core object, reused.** SpatialData's layer stack and muon's isometric container are drawn once in detail and then used as a small icon wherever the object flows. The U-Chrom draft has a logo glyph, but the object is drawn three different ways (a card with 10 buttons in a, a block diagram in b, and "ChromData" as text in c).
2. **Colour is semantic or absent.** The best figures (scvi-tools, muon, Seurat v5, SpatialData) use 2–4 meaning-bearing hues on a greyscale scaffold. Colour appears on *text, outlines, header bars and small glyphs* rather than on large fills.
3. **At most 3–4 type sizes, one family,** with hierarchy from weight and position. Panel titles are short noun phrases, with no citations in titles.
4. **Real data sits in uniform tiles.** SnapATAC2, muon and ArchR put heterogeneous plots in equal-size tiles, often greyed or on a faint grey ground, with one colour highlight. They never use full rainbow colormaps side by side.
5. **A strict grid with shared gutters.** Panel edges align across rows, and there are no "floating" boxes.
6. **Arrows are few and thin.** Flow is carried by position (left → right) and containment (scverse, Squidpy) more than by arrows.
7. **Show the API once** (a scvi-tools-style code block), rather than code captions everywhere.

## 4. Design brief for the U-Chrom Fig 1 redesign

### 4.1 References to emulate (in order)

1. **MuData/muon.** The closest conceptual twin: a container of modality-specific tables, in-memory ↔ HDF5, in the same journal. Borrow the exploded isometric container, the *name / type* two-tone labels, and the grey real-data thumbnails with semantic highlights.
2. **SpatialData.** Borrow the recurring core glyph, one accent colour for panel titles, uniform flat icons and the tight modular grid.
3. **scvi-tools.** Borrow the slate structure colour with modality colours only on text and glyphs, the left → right pipeline with zoom-in callout, and the `cd.*` code block.
4. **Vitessce (panel c).** Borrow matrices with semantic colour header bars, an explicit observation-coordinates (x, y, z) strip, and tinting of present vs absent data.
5. **Nucleome Browser / cooltools** for the domain vocabulary. Nucleome Browser shows how Hi-C, FISH and 3-D structures sit together as real data. Cooltools shows tool names as badges on arrows.

### 4.2 Recommended layout (170 mm wide × about 175 mm tall)

Use a 12-column grid with a 3 mm gutter. Column width is about 11.4 mm.

```
┌──────────────────────────── 170 mm ─────────────────────────────┐
│ a  (cols 1–12, ~62 mm tall)   ONE continuous story row          │
│ ┌ Inputs ┐  recon/im   ┌──── ChromData (HERO) ────┐  ┌Modules┐  │
│ │seq card│ ─badge──▶  │ cell → trace → spot       │  │strc   │  │
│ │ (teal) │            │ exploded block diagram    │─▶│fea    │  │
│ │img card│ ─badge──▶  │ spots│coords│tracks ...   │  │emb    │  │
│ │(orange)│            │ .h5cd ↔ linked .mcool...  │  │pl     │  │
│ └────────┘            └───────────────────────────┘  │browser│  │
│  cols 1–3              cols 4–9 (≈85 mm)             └cols11-12┘ │
├─────────────────────────────────────────────────────────────────┤
│ b  (cols 1–7, ~50 mm)  hierarchical access │ c (cols 8–12)       │
│  FOV → nucleus → trace (3 tiles, 1 row)    │  `cd.*` code block  │
│                                            │  (8–10 lines)       │
├─────────────────────────────────────────────────────────────────┤
│ d  (cols 1–12, ~48 mm)  the same container across modalities    │
│  5 equal tiles (≈31 mm each), semantic header bar per tile      │
└─────────────────────────────────────────────────────────────────┘
```

- **Merge the current a and b.** The ChromData anatomy *is* the hero, and it sits in the centre of the workflow. Inputs enter from the left, and modules leave to the right. This removes the duplicate 10-button attribute grid in the current panel a and removes about 60 mm of height.
  - Hero proportions: about 85 mm wide × 55 mm tall. Draw it as an AnnData/MuData-style exploded block diagram.
  - The `spots` table carries the cell/trace colour bars. `coords` gets its (x, y, z) stack, and `layers` sits behind it as offset copies. `tracks` goes to the right.
  - `cells`, `cellm` and `traces` sit above or right as per-cell/per-trace blocks.
  - `points`, `results` and `uns` are a row of small cards at the bottom, in FOF-CT card style: name in bold monospace, then a grey type word.
  - The `.h5cd` label and the three dashed "linked, not copied" file chips hang under the hero, joined by one thin dashed line.
- **Inputs (cols 1–3)** are two compact cards, each with one real-data micro-thumbnail and 3 format names:
  - Sequencing: a 12 mm contact-map glyph (HiGlass style), then Hi-C · scHi-C · multiome.
  - Imaging: a 12 mm spot-image or trace glyph, then chromatin tracing · DNA seqFISH+.
  - No bullets. Formats go on one grey line (`.pairs .mcool .scool .hic` / `FOF-CT`).
- **Structure generation** becomes cooltools-style pill badges *on the arrows* (`recon` on the teal arrow, `im` on the orange arrow). The direct-read path for imaging (FOF-CT) is a second, thinner orange arrow that bypasses the badge. This replaces the two long wrap-around dashed routes.
- **Modules (cols 11–12)** are a vertical list of 5 rows. Each row has a 4 mm monochrome glyph (TAD triangle, feature bar, embedding dots, plot axes, browser window) plus `strc` / `fea` / `emb` / `pl` / `browser` in monospace, with one grey descriptor underneath. Use one bracket or arrow from the hero, not five.
- **b (hierarchical access)** has 3 equal square tiles (about 30 mm each) in one row with thin arrows: FOV of 47 cells → one nucleus → one trace. The accessor call (`cd.get_cell(...)`) goes under each tile in monospace. Put the cell-type legend in one row under the first tile, or drop it and grey out all cells except the selected one.
- **c (API)** is a scvi-tools-style code block of about 8 lines: `ChromData.read`, `get_cell`, `get_trace`, `compute_distances`, `link_mcool`, `strc.tad…`, `write`. Use a pale grey background (#f3f4f6) with syntax colours drawn only from the palette. This absorbs the per-tile code captions from the current panel d.
- **d (modalities)** has 5 equal tiles, each 30 × 30 mm of plot area. Each tile gets a 1.5 mm header bar in its semantic colour (Vitessce style) with the modality name in white or dark text. Put one grey context line under each plot, and use the same axis style in every tile.

### 4.3 Typography (sizes at final print size)

| Role | Size | Weight | Colour |
|------|------|--------|--------|
| Panel letter | 8 pt | bold, lowercase | #222 |
| Panel title (noun phrase, sentence case, no citation) | 7 pt | bold | #222 |
| Primary labels (object names, stage names) | 6 pt | regular or medium | #222 or semantic colour |
| Secondary labels, axis labels, context lines | 5 pt (minimum) | regular | #6b7280 |
| Code / API names | 5.5 pt | regular | Menlo / DejaVu Sans Mono |

- Use only these 4–5 sizes, with Arial/Helvetica throughout. Nothing may be below 5 pt after scaling.
- Use monospace **only** for real Python identifiers. Put citations such as "Takei et al. 2025, DNA seqFISH+" in the legend, not in the title.
- Line weights: 0.5 pt for structure strokes, 0.35 pt for grid lines inside blocks, 0.75 pt for flow arrows, and 1 pt for the hero outline. Nothing thinner than 0.25 pt.

### 4.4 Palette

Keep the three semantic hues. The references confirm that 2–3 semantic hues on grey is the professional pattern:

| Token | Hex | Use |
|-------|-----|-----|
| SEQ | `#2a9d8f` | sequencing inputs, contacts, Hi-C recon, linked `.mcool/.scool` |
| IMG | `#e07a3f` | imaging inputs, FISH coords, IF/RNA spots |
| CORE | `#34568b` | ChromData, its tables, code identifiers |
| INK | `#222222` | text |
| GREY-1 | `#6b7280` | secondary text, module glyphs |
| GREY-2 | `#d1d5db` | strokes, grid lines, de-emphasised data |
| TINT-SEQ / TINT-IMG / TINT-CORE | `#e8f5f3` / `#fcefe6` / `#e9eef6` | panel backgrounds only; never under text-heavy boxes |

**Rules:**
- Colour means provenance: teal = came from sequencing, orange = came from imaging, and indigo = lives in ChromData.
- **Do not colour `tracks` orange.** ATAC/ChIP tracks are sequencing-derived, and IF is imaging-derived. Colour `tracks` CORE, like every ChromData table, and let the column headers carry a small teal or orange dot for provenance.
- **Drop the purple** used for `cells` / `cellm`. It is a fourth, meaningless hue.
- **Data colormaps:** one sequential map for all matrices, for example a single-hue indigo-to-white or `viridis` for distances plus `fall`/`YlOrRd` for contacts. At most two colormaps across the figure.
- **Genomic position along a trace:** use a 2-colour ramp (light → CORE, or teal → orange) instead of rainbow `jet`/`turbo`.
- **Cell types:** a muted categorical set (for example Okabe-Ito desaturated), or grey all cells except the one highlighted.

### 4.5 Icons and illustration

- Draw every icon in **one flat vector style**: 0.5 pt stroke, 2–3 fills from the palette, rounded corners at 0.8 mm. Draw them in matplotlib/Illustrator yourself, not with an image generator.
- **Remove the raster AI illustrations** (the microscope clip-art, the circular nucleus image, the Hi-C arc sketch). Replace them with:
  - a triangle or square contact-map glyph (HiGlass style) for sequencing;
  - a nucleus outline with 5–6 coloured spots joined by a polyline (a tracing glyph, echoing FOF-CT) for imaging.
- **3-D renderings:**
  - Render one trace at a time as a tube or ball-and-stick with a 2-colour genomic ramp and light shading.
  - For whole-cell / whole-genome renderings, colour by chromosome with at most 4 highlighted chromosomes and the rest grey at 30 % alpha. Never show a 20-colour hairball (Nucleome Browser's "Global map" is the upper bound).
- Use the ChromData logo glyph (the layered stack) as the recurring icon wherever the object appears (hero, b, API), as SpatialData does.

## 5. Critique of the current draft (`paper/fig1/fig1_overview.png`, 180 × 208 mm)

**Global**
1. **Wrong page size.** It is 180 mm wide, but Genome Biology full width is 170 mm, with at most 225 mm including the legend. Everything will shrink by about 6 %.
2. **16 font sizes (4.2–9 pt) in `make_fig1.py`.** Eleven of them are ≤ 5.4 pt, and several labels (4.2–4.6 pt: colourbar ticks, rotated column headers, context lines) will print below 4 pt after scaling. *Fix:* use the 5-size scale in 4.3.
3. **Three visual registers fight:**
   - raster AI illustrations (microscope, nucleus, Hi-C sketch, the 3-D logo);
   - flat vector boxes;
   - dense real-data renderings.

   *Fix:* use one flat vector icon set and real data only in uniform tiles.
4. **The core object is drawn three times** in three styles: the card with 10 buttons in a, the block diagram in b, and "ChromData" as monospace text in c. *Fix:* merge a and b so the anatomy diagram is the hub of the workflow (4.2), and reuse the logo glyph elsewhere.
5. **Too many hues.** In addition to teal, orange and indigo there is purple (`cells`), grey (`traces`), blue-grey (`spots`), a six-colour cell-type palette (blue, red, yellow…), a rainbow trace map, viridis, YlOrRd, a UMAP palette and the jet hairball. *Fix:* follow the palette rules in 4.4.
6. **Semantic colour conflict.** `tracks` is filled orange (the imaging colour) but shows ATAC. Cell-type red/blue look like the seq/imaging colours. Panel-d titles are coloured teal/orange, while their data use unrelated colormaps.

**Panel a**

7. **The title banner wastes about 5 % of height.** The logo and "one data model for…" subtitle belong in the paper, not in Fig 1. If you keep it, make it a 6 mm strip.
8. **Slide-deck bullet lists** in the input cards and plain text lists in the recon/im boxes. *Fix:* use format names on one grey line, and put module names as badges on the arrows.
